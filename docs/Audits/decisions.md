# Audit Decisions Ledger

Durable dispositions from past audit passes. Check this ledger before confirming a candidate; do not re-propose a dispositioned item unless the evidence has changed (new callers, new drift, changed ownership). This is the only file under `docs/Audits/` that records outcomes — run logs, Done tables, and dated status still do not belong in the audit guides.

## How to use

- Before confirming a finding, search this file for the subject path or symbol. A row suppresses only the recorded candidate and remedy, not new evidence or a broader finding that happens to involve the same file.
- When a pass ends with a rejected or deferred proposal, or a borderline candidate is intentionally kept, add one row.
- Keep entries to one line each. Link evidence in the commit or PR, not here.
- Remove a row when its subject is deleted or the disposition no longer applies; note the removal in the commit message.
- Record a concrete revisit condition. Use `never` only for stable architectural or compatibility policy; fast-changing implementation decisions should name the evidence that would invalidate them.

Dispositions: **keep** (intentional under the recorded evidence — do not re-flag until the revisit condition holds), **rejected** (proposal declined — do not re-propose until the revisit condition holds), **deferred** (approved but unscheduled — re-raise only when the user asks or the revisit condition makes it newly urgent).
